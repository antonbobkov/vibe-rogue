# DECISIONS

Ambiguity log (`40-implementation-plan.md` § PLN-07.1). One row per decision taken where a rule was
missing, ambiguous, or self-contradictory. Rows are append-only; IDs are never reused or renumbered.

| ID | Spec IDs | Question | Decision | Why | Milestone |
|---|---|---|---|---|---|
| D-001 | PLN-02 R2, TEC-02 | R2 exempts "the storage adapter in `save.js`", not the whole file. How does `dom-free.test.js` express a partial exemption? | `src/save.js` is scanned like any other core module, but the single identifier `localStorage` is permitted in it. `src/render.js`, `src/main.js` and `src/screens/*` stay fully exempt. | Keeps R2 enforced over the rest of `save.js` (serialize/deserialize must stay headless) while allowing exactly the adapter TEC-09 requires. | M00 |
| D-002 | PLN-02 R2, R3 | Should the R2/R3 scanners match forbidden text inside comments and string literals? | No. Both scanners strip comments and string bodies before matching; `${...}` interpolations inside template literals are kept, because they are code. | Item and script data (`data/*.js`, `SCR-10` templates) contain English prose that would otherwise trip on words like `function`, `class` or `window`, producing false failures that R10 forbids fixing by renaming spec content. | M00 |
| D-003 | PLN-04, PLN-06 M00 | `npm test` must run the unit, integration and meta tiers but not the Playwright specs. `node --test test/` cannot express that. | `npm test` runs `node tools/dod.js --node`, which discovers `test/**/*.test.js` itself and passes the explicit file list to `node --test`. | `node --test <dir>` treats *every* `.js` file under a directory named `test` as a test file, so it would try to execute `test/e2e/*.spec.js` and `test/fixtures/*.js`. Positional glob patterns need Node ≥ 22, but PLN-04 fixes CI at Node 20. | M00 |
| D-004 | PLN-04 | PLN-04 describes the DoD as "`node --test` filtered by milestone tag, then the meta tests". Are the meta tests included in the filtered run as well? | No. Step 1 runs `test/**/*.test.js` outside `test/meta/` with `--test-name-pattern`; step 2 runs `test/meta/*.test.js` with no filter. | The repo rules (R2, R3, R5, ACC coverage) always apply in full, and splitting the two steps avoids running the meta tier twice per DoD. | M00 |
| D-005 | PLN-02 R4, PLN-07.4 | R4 requires an exact `@playwright/test` pin but names no version. | Pinned `1.63.0`. | Latest stable at scaffold time; every `playwright < 1.55.1` carries a published advisory (GHSA-7mvr-c777-76hp), so the pin also keeps `npm audit` clean. PLN-07.4's downgrade path was not needed — the Chromium download succeeded. | M00 |
| D-006 | TEC-08, ENM-08, PLN-06 M01 | The plan fixes the names in `grid.js` but not the shapes: what is a tile, what does `bfs` return, and what exactly is in an `astar` path? | A tile is `{x, y}`; a tile index is `idx(x, y) = y * 60 + x`. `bfs(passable, starts)` returns an `Int32Array(W * H)` of step distances with `-1` for unreachable, and accepts one start or many. `astar(passable, from, to, {maxLen})` returns the steps **after** `from` up to and including `to` (`[]` when `from === to`, `null` when there is no path within the cap). `neighbors8` is clipped to the map and returned in reading order. Passability is always the step callback `(from, to) => boolean`. | The step callback is the only shape that can carry the ENM-08 door-diagonal rule, `opensDoors`, hazards and occupancy without `grid.js` knowing what a tile is — ENM-08 makes all four caller-specific. "Steps after `from`" is what ENM-06's "take the first step of the path" needs (`path[0]`), and the typed array keeps the WLD-11 step-5 room BFS allocation-free. | M01 |
| D-007 | TEC-08, CMB-08 | TEC-08's Bresenham excludes the start and includes the end. What does a degenerate line (start = end) return? | `[{x0, y0}]` — the single tile. | It is what the algorithm as written does: it stops "once `(x1, y1)` has been emitted", and with `dx = dy = 0` neither branch fires, so the first emission is the start tile, which is also the end tile. "End included" wins over "start excluded" because CMB-08 uses the path to find what a projectile hits, and a projectile aimed at your own tile lands on it. | M01 |
| D-008 | WLD-05, TEC-08, ACC-78 | ACC-78 requires the FOV to be symmetric, but the reference symmetric-shadowcast reveals a *wall* whenever a scan line touches it, without the `is_symmetric` check — so wall visibility is not symmetric. Which tiles does the symmetry claim cover? | Symmetry is asserted over pairs of non-blocking tiles, which is exactly what WLD-05's "Tick sees the enemy ⇔ the enemy's shadowcast reaches Tick" needs, since actors only ever stand on passable tiles. Walls are revealed by the reference's rule so that "walls at the edge are visible" (ACC-78) holds. Tiles off the map are treated as blocking, and the scan stops past the radius, which is identical to computing the full cast and then applying the Chebyshev filter (within a quadrant the scan depth *is* the Chebyshev distance). | This is the reading under which every clause of ACC-78 passes at once; the alternative (running the symmetry check on walls too) makes room walls flicker in and out and contradicts WLD-05's "the wall you can see is drawn". | M01 |
| D-009 | ITM-10, PLN-06 M01 | A loot table is a list of `(itemName, weight)` pairs. Does `weighted(rng, table)` return the pair or the name? | The entry's first element — the item name. Weights must be positive integers, and exactly one draw is consumed. | Every caller in `12` and `21` wants the name; returning the pair would make each call site index into it. Rejecting non-positive weights turns a mistranscribed table (M02) into a loud failure rather than a silent bias. | M01 |
| D-010 | TEC-03, TEC-07 | TEC-03 gives three dice spellings (`2d4+1`, `1 (flat)`, `1`) but no grammar; `23-floors.md` also uses `0d1+1`. | `parseDice` accepts `NdS`, `NdS+M`, `NdS-M`, a bare signed integer, and an integer followed by `(flat)`, case-insensitively and ignoring surrounding whitespace; anything else throws. Both flat spellings give `{n: 0, sides: 1, mod: value}`, so `roll` consumes no draw for them. A `Dice` object is passed through unchanged. | TEC-03 fixes flat `1` as `{0, 1, 1}` and TEC-07 fixes `roll` as "sum of `n` calls plus `mod`", so `n = 0` is the only encoding of a flat value that spends no randomness — which the call-order guarantee of TEC-07 depends on. Throwing on anything else keeps a typo in the M02 transcription from silently becoming `1d1`. | M01 |
| D-011 | WLD-05, CMB-08, TEC-08, TEC-11 | WLD-05 and CMB-08 both cite `TEC-11` for the exact FOV and Bresenham variants, but `TEC-11` is Input; the algorithms are in `TEC-08`. | Read both as `TEC-08` and corrected the two cross-references in the prose (PLN-07.1 step 3). No rule, number or ID changed. | `TEC-08` is titled "Deterministic algorithms" and contains both the Bresenham form and the Albert Ford FOV reference the two sentences describe; `TEC-11` contains neither. | M01 |
